SelfMe Lab · 2026-09-26 审计 · 当前已实现范围，不代表未来模块已落地

原则：应用自主拥有的会话数据进入 SQLite；少量可读偏好与 Provider 连接进入配置文件；第三方 Harness 的原生上下文由其自身格式保管，不能强行改造成应用数据库。

必要例外与边界

类别实际位置为何不进应用 SQLite
Harness 原生上下文userData/runtime-homes/<runtime>/<session-id>/DSH、Codex、Pi、Kimi Code 各自写会话、索引、状态、日志或缓存。恢复原生上下文依赖这些格式；应用 SQLite 只保存关联标识和可展示事件。
Harness 派生配置上述目录中的 Codex config.toml、DSH selfme-model.patch.yml 等由当前 Provider 配置重新生成，符合配置文件原则；不保存明文 API Key。
Electron / Chromium 内部数据userData/Cache、Code Cache、Session Storage、Local Storage 等框架管理的缓存、浏览器状态或内部数据库；应用业务代码不以它们保存新数据。旧版四个工作目录 Local Storage 键会先迁移至 app-config.json，再逻辑删除。LevelDB 日志里的历史字节可能要等框架压缩才消失。
旧版 Harness 目录userData/{dsh,codex,pi,kimi}-home/升级前的原生数据。新代码已不引用；暂不删除，避免破坏用户旧会话。
短暂界面状态React 进程内存输入框草稿、筛选、展开状态，以及当前 JEV 棋盘、走棋历史、决策详情目前只在本次打开期间有效；关闭后不恢复。JEV 若要保存棋局，需要新增 SQLite 表，不能误称已持久化。
静态实验内容与构建物源码中的 Atlas 目录/覆盖标注、design/、assets/、runtimes/、out/、release/、.work/、.cache/源码、设计资产、内嵌运行时、打包产物或被 Git 忽略的开发缓存，不是用户会话存储。Founder Studio、Harness Forge、RSI Lab、Remote Agent Lab、Local Model Lab 尚无业务数据写入。

安全与后续约束

  • 当前用户数据目录为当前用户可访问，应用数据库与配置文件为 0600；数据库内容不做额外的整库加密，因此任务输入和工具输出可能包含敏感内容，应按敏感本地数据处理。
  • 新增持久化功能时，先决定是会话/事件型数据（SQLite）、少量用户可编辑配置（配置文件），还是 Harness / Electron 自主管理的必要例外；不要再以 Local Storage 承载业务数据。
  • 现阶段不迁移、不删除旧版 Harness 目录，也不清空整个 Chromium 存储。只定向迁移并移除旧工作目录键。
